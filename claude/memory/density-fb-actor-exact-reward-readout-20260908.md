**Fact (verified 2026-09-08, `impls/critics/density_fb.py:973-989`, `impls/actors/flowbc.py:73-83`).** The actor's value is not F·B and not F·z. It is Σ_m w_m·kg_m with w = softmax over the batch's M=256 next-state candidates of F(s,a,c)·B(u_m)/τ (two heads, min), and kg = the reward at each candidate, stop-gradiented. Goal arm: kg = exp(−½Σ_blocks‖(g−u)/0.4‖²) (`:354-373`, sum inside the exponential ⇒ PRODUCT over object blocks ⇒ conjunction), 0.4 in the env's ×10-scaled coords = 0.04 m = OGBench cube success radius (`cube_env.py:715`). Measure loss's immediate term with the hard setting is a one-hot at the own next state (`:911-917`), so the kernel enters ONLY the actor readout. z arm (`measure_density_z_actor_reward` latent / latent_centered): kg = B(u)·z/√d, FB's linear reward proxy. Theory: Q^π_r = ∫ m^π r; FB reads the projection of r onto span(B) (exact iff r ∈ span B); ours is a self-normalized importance-sampling estimate of the same integral for any bounded r. Probe on frozen B (cube-double, seed 0): linear fit of the both-cubes reward R2 ≈ .05, product of two per-cube linear fits recovers the AND; critic/actor accept one linear z only.

**Why:** the user found this via another session and said it "changes the whole method"; the paper (PAPER/ICLR) is framed as a BFM paper, so a goal-only readout is not publishable.
