Bridge / measure track. Spec `PAPER/Multistep-FB/specs/24-z-indexed-density.md`.
Code `67fc08e`, E2 eval `bd4efb5`. Follows [[spec18-density-measure-20260806]].

**The question.** Density-FB indexes its policy family by goals; FB indexes by a
latent z. Spec 24 swaps ONLY the index and keeps the CE/softmax estimator
byte-identical, to ask whether the density estimator is a drop-in inside FB's
full interface.

**E1 (goal reaching) — the answer, and it is negative.**

| | z-indexed | g-indexed | BC floor |
|---|---|---|---|
| point-mass-maze | .200 ± .062 (3s) | .315 | .235 |
| **cube-double** | **.017 ± .025 (3s)** | **.736** | **.019** |

Cube-double is the load-bearing cell: z collapses to the behavior-cloning floor
from .736. ⚠ On pmm do NOT say "below BC" — BC (.235) sits inside the z arm's CI
[.138, .262]. The licensed pmm comparison is against .315, which is outside it.

**It is not a training failure.** z_cos_spread .34–.35 on every seed (no index
collapse), and CE / ESS / k_self match the g-indexed comparators almost exactly
(cube-double k_self .515 vs .515; the parallel audit measured CE 5.894 vs 5.856
and ESS 299 vs 296 on pmm). The measure under z trains normally; the
z-conditioned ACTOR is what never extracts.

⚠ **Do NOT close this as "goal indexing is load-bearing, use goals."** Two
things forbid it. First, the parallel audit identified mechanistic reasons z≈BC
needs no bug at all: `z_rand_frac=0.5` means half the actor's rows train on
RANDOM z (FB's standard mix, but it dilutes the BC signal), and the z(g)
encoding is non-stationary because it is built from the moving target-B tower.
Spec 24 anti-scoped a z_rand_frac sweep, so neither has been tested. Second, the
user's binding requirement is a FULL successor measure with a general reward
interface; goal-conditioned-only is explicitly not acceptable as an end state.
So the defensible claim is that *this* z-extraction recipe fails, not that
goal indexing is necessary.

**E2 (reward readout) — UNINFORMATIVE, and only the control revealed it.**
E2a (analytic z_r) ≈ E2b (search) ≈ .003–.023 across families, which against the
goal-conditioned anchors looks like "z destroys reward readout". It is not:

| arm | dirac | dense | region | success_any |
|---|---|---|---|---|
| E2a | .005 | .005 | .023 | .36/.39/.37 |
| E2b | .003 | .003 | .010 | .37/.38/.32 |
| **control (g-indexed)** | **.000** | **.000** | **.000** | .38/.38/.43 |

The g-indexed control reads ZERO too. `success_final` needs the point mass to END
inside a .03 ball after a 1000-step episode with no termination; every arm fails
it while `success_any` shows all of them visiting the region 32–43%. The protocol
is saturated. **Method lesson: an eval that reads ~0 for every arm is a broken
instrument, not a result — always run the matched control before interpreting a
floor.** Comparing E2 to the goal-conditioned anchors (.315/.242/.235) would have
been a protocol-mismatch error of the same class as the spec-17 cross-harness
region trap.

**E2 RERUN on cube-double (2026-08-13) + the G4 probe that actually answered it.**
E2 was rerun where the metric discriminates. Control (g-indexed) reads
.464/.552/.300 on dirac/dense/region; both z arms read .000-.029 everywhere,
E2a ≈ E2b within .02. ⚠ But this STILL does not isolate the readout: E2 scores
`success_final`, a full pipeline ending in an actor rollout, and the z actor is
already dead at goal-reaching (E1 .017). A metric terminating in a dead actor
reads ~0 whatever the readout does. Same class of trap as the pmm saturation,
opposite sign — confounded with a failure already measured.

The actor-INDEPENDENT instrument is `scripts/rescuing_fb/eval_measure_g4_spearman.py`
(correlates model readout masses against an MC estimate; needed two eval-only
fixes to run here: z-encode the readout via `agent._density_z_encode`, and a
hindsight per-start query path because `build_fixed_queries` degenerates on
conjunctive envs). Result, `spearman_tie`, gate ≥.65:

| ckpt | pooled | degenerate_frac | mc>0 subset |
|---|---|---|---|
| z_s0/s1/s2 | .766/.759/.807 | .545/.597/.543 | .672/.773/.800 |
| control (g) | .739 | .635 | .666 |

**The z measure is calibrated, and the z policy is NOT frozen** — it enters MORE
boxes than the working control (lower degenerate_frac), so the high score is not
a trivially-predictable-degenerate-policy artifact (I checked this specifically).

⚠ **Do NOT write "the full successor measure exists under z and only extraction
is missing."** G4 rolls the agent's OWN policy, so it is a SELF-CONSISTENCY test:
it shows the measure faithfully predicts the occupancy of the policy it trained
alongside. Successor measures are policy-relative (M^π models π); a faithful
model of a non-goal-directed policy does not establish a goal-directed one is
extractable from it. What IS ruled out: the measure being internally broken.

**Live suspect = the index.** The actor maximizes r_z = B(u)ᵀz. If z(g) is a lossy
encoding of g, maximizing r_z need not reach g, and measure and policy would still
agree about where the policy goes — precisely the observed picture (calibrated,
mobile, not goal-directed). This gates fork B: a decoupled actor head that still
conditions on z inherits a lossy index. Actor-independent z-retrieval test
(does z(g) retrieve its own goal?) dispatched 2026-08-13, `results/spec24_eval/zid_*.json`.

**z-INDEX IDENTITY TEST (`scripts/rescuing_fb/eval_z_identity.py`, actor-free):**
encode pool goals with the agent's own `_density_z_encode`, cosine-NN retrieve,
score by hit-spec eps-ball membership. top1: z .738/.750/.792, control .782.
⚠ Read those against TWO baselines the first report omitted, both computed here:
**chance top1 = .0005** (mean 7.8 of 16383 pool points inside a ball) and
**ceiling top1 = .818** — 18.2% of queries have NO other pool point in their own
ball and auto-fail. So z reaches 90/92/97% of achievable vs the control's 96%,
at ~1500x chance. `nearest_wrong_cosine ≈ 1.0` for ALL four ckpts incl. control:
saturated, uninformative, do not quote. **The index is NOT lossy.**

**Where this leaves the chain.** E1 goal-reaching .017 (dead) + G4 measure
self-consistent .76-.81 (vs control .74) + index informative ≈ ceiling ⇒ the
measure models its own policy well AND the index identifies goals well AND the
policy still does not reach goals. That isolates the defect to the EXTRACTION
step, and licenses §9.16 fork B (decoupled test-point-grounded actor head) on
evidence rather than assumption. ⚠ But cheaper untested explanations come FIRST:
`z_rand_frac=0.5` means half the actor's rows train on random z, and z(g) is
non-stationary (built from the moving target-B tower). A z_rand_frac ablation is
far cheaper than fork B and is the correct next experiment.

**Consequence for the program.** The §9.16-fork-B decoupled test-point-grounded
actor head is NOT licensed by this: it was gated on E2 showing the z-measure's
readout works, and E2 showed nothing. To pursue it, either rerun E2 on
cube-double (where the goal metric discriminates, g-indexed .736) or fix the pmm
metric first (report success_any, or terminate on region entry).

**Two implementation traps this cost.**
1. The first z build crashed at launch: `sample_actions` (the entrypoint
   `evaluate()` calls every env step) had no z branch and passed the raw 4-dim
   goal into an actor registered 50-wide. 8/8 unit tests passed because every one
   constructed an agent or ran `update()` and none drove the eval path. **Make a
   real training step the acceptance criterion, not a construct-only check.**
2. Its obvious fix reintroduced a second shape bug, since the query helper slices
   with an explicit batch axis and eval calls it unbatched.
