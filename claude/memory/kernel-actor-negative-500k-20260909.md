**USER FRAMING (2026-09-10):** the whole issue is the TASK DISTRIBUTION the actor is trained on and the reward each task carries. Original FB: 50% z = B(next state), 50% random sphere, ALL with reward B(s')·z (homogeneous). Our campaign z model: 50% hindsight-goal z + 50% sphere, all B·z (= FB's distribution, only the critic differs). Our exact-reward variant: same split but goal tasks carry the true success reward and sphere tasks keep B·z ⇒ two reward forms in one loss, sphere half swamps goal half ⇒ failed; dropping sphere tasks fixed cube-single but broke scene Route B (actor never trained where the reward-sample z lands). Sweep in tmux `kz_scene` tests 10% / 25% sphere. Principled fix if the sweep fails: give sphere tasks an exact reward too (decode a goal from the random z) or normalize the two row types separately. State this in the paper as 'the actor's task distribution and its reward'.
