$^{\mathrm{r}}$: the task vector comes from a hindsight goal in the same trajectory, read out by the reward regression of Appendix~\ref{app:task-index}. Density cells without this mark keep the host method's own rule for choosing a task vector, which is what makes them level with the plain backbone --- the matching $^{\mathrm{r}}$ runs on cube-double, scene and puzzle-3x3 have not been done, so the two retrofit averages are not yet a measurement of the objective.
Every column reads the full state: no method here is given object coordinates. Density-FB is density\_fb\_z\_state, which exists only on the two cube environments --- the scene and puzzle-3x3 runs at full state have not been done, so that column has no average. With object coordinates in the backward network the same method reaches 81.3$\pm$3.8 / 30.4$\pm$2.6 / 52.7$\pm$3.3 / 4.7$\pm$0.9 on the four tasks; that input costs it cube-single ($90.9\to81.3$) and buys it cube-double ($15.8\to30.4$).
\textbf{avg} is the mean of the four rows, recomputed per column; no spread is carried through the recomputation.
On cube-double, reward inference is capped near half of goal-conditioned success for every method: OGBench re-permutes the cube-to-target assignment at every reset, while the reward samples used to infer $z$ encode one fixed assignment. Under goal conditioning Density-FB reaches 68.6$\pm$1.0 there and 93.1$\pm$1.5 on cube-single.
