## 0. Verdict summary

**No fatal code bugs.** The bilinear implementations are faithful (GCIQL/GCIVL reuse
OGBench's own stock `GCBilinearValue`; HIQL's `_BilinearRepValue` verified to share
`goal_rep` params with the actors — no duplicated subtree, flax dedupes by instance;
target-value uses the online rep exactly as stock HIQL does). The problems are
**experiment hygiene and claim calibration**, not wiring:

| Issue | Impact |
|---|---|
| **Param confound**: bilinear value = 2.26M params vs MLP 1.10M (**2.06×**, measured) | Every bilinear-vs-MLP cell. BVN matched params; reviewers will demand a control |
| **alpha mismatch on cube DDPG+BC**: stock cube uses α=1.0, bilinear-d50-ddpgbc used α=0.3 | The "bilinear hurts DDPG+BC on cube" cell (51–57 vs 67–70) is confounded |
| **GCIVL-Flow-Bilinear group mixes a dead batch** (June-29 18:18: two finished runs at 0.000 + one crash) with a healthy batch (.788/.796/.792) | The paper's "bimodal 47.5±38.8" is a **bad-batch artifact**, not seed bimodality. Healthy number: **0.792** — the biggest GCIVL win, currently underclaimed |
| **Seed bookkeeping**: "10 seeds @1M" grids are really 7 @1M + 3 @500k (only d512 has 0–9 @1M, with s3/s7 failed mid-run, never rerun); duplicate run names across relaunch batches | Headline means need recomputation; clean seed sets needed for the paper |
| **HIQL sg=25 bug** (known): all old HIQL cells mistuned | sg10 rerun IN FLIGHT — early result **flips the conclusion** (see §2) |
| **Protocol vs published**: ours = single eval @500k (some @1M), 3–10 seeds, 50 eps/task; OGBench = 1M, 8 seeds, 20 eps/task (verify their avg-of-final-evals rule from the paper) | SOTA claims need matched-protocol reruns |
| **Antmaze claim overreach**: 83.7 beats *GCIQL's* 71 but published HIQL holds antmaze at **96** | Antmaze win is method-relative, NOT domain SOTA. Cube (≈0.93 @1M vs best-published 68 across ALL methods) is the genuine domain-SOTA claim |
| **Form inconsistency across methods**: GCIQL/GCIVL bilinear = Schaul form ψ(g); HIQL bilinear = BVN form ψ(goal_rep([s;g])) | Not a bug — an unexploited ablation axis (BVN claims ψ(s,g) is required; our cube data contradicts that for GCIQL) |
