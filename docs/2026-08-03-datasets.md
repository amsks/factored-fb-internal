# The datasets behind `PAPER/decoding-bilinear/table.tex`

*Status: reference, 2026-08-03. Companion to `PAPER/decoding-bilinear/table.tex` (the
critic×actor grid + the kill-test arms) and `phenomenon.tex` (the pre-registered
hypotheses those arms test). Every statistic below was recomputed from the packed
`.npz` files under `$SCRATCH/fb-data/`, not copied from the paper.*

Six distinct datasets appear across the two tables. The main grid uses `expert` and
`play-noise`; the kill-test table adds `play-noise-hard`, `play-resample`,
`play-resample-hard`, and the cube arms train on stock OGBench `cube-single-play-v0`.

## 0. Common schema

Each dataset is one packed npz per task at `<root>/data/<family>/<task>.npz`, with the
8 unified fields stacked `[N, T, ·]`:

    observation, action, next_observation, achieved_goal, reward, terminal, timeout, success

`env/unified.py::load_packed` flattens to `N·T` transitions and **synthesizes** the
`terminals` that mark trajectory boundaries at each episode's last step — the env's own
`terminal` flag never fires, since every collection here is fixed-horizon.

Two schema facts matter for reading the results:

- `achieved_goal` is a **zeros placeholder** in all six (`collect_mw_standalone.py:83`).
  Nothing reads it.
- The eval goal for the goal-conditioned critics does not come from the data's goal
  field either. It is the single highest-reward `next_observation` in the dataset
  (`env/unified.py:167`) — one fixed frame, reused for every eval episode. The
  `play-resample` arm deliberately does **not** touch this (train-side repair only).

## 1. `expert` — ManiSkill (`ms-pick-cube`, `ms-push-cube`)

**Generation** (`data_collection/collect_expert.py`): rollouts of the pretrained newt
TD-MPC2 checkpoints (HF `nicklashansen/newt`, snapshot `7eef11e`), planner on, zero
exploration, 50 parallel envs, `success_only=false` so failures are kept. newt's
multitask obs/action padding is stripped back to the raw env dims. On disk these are
symlinks into `hf_export/` — the published Factor-FB-Offline pack, not regenerated here.

**Contents**: 1000 episodes × 25 steps (10 Hz) = 25k transitions each.

| task | obs | act | ep-success | dwell (frac steps at goal) |
|---|---|---|---|---|
| `ms-pick-cube` | 42 | 4 | 0.996 | 0.746 |
| `ms-push-cube` | 35 | 7 | 0.999 | 0.858 |

## 2. `expert` — Metaworld (`mw-pick-place`, `mw-push`)

**Generation** (`data_collection/collect_mw_standalone.py --regime expert`): the
published pack has no `mw-pick-place`/`mw-push`, and the play counterpart
(`TommyShen/factored-fb-play`) is unreachable, so both were regenerated from Metaworld's
built-in **scripted oracle** (`SawyerPickPlaceV2Policy`, `SawyerPushV2Policy`) — torch-free,
no TD-MPC2 checkpoint. The `expert` branch forces `eps = noise = 0`
(`collect_mw_standalone.py:59`), so this is the deterministic oracle. Env is
`env/metaworld_env.py` (action-repeat 2, horizon 100), byte-identical to the eval env.

**Contents**: 1000 × 100 = 100k transitions, obs 39 / act 4.

| task | ep-success | dwell |
|---|---|---|
| `mw-pick-place` | 1.000 | 0.749 |
| `mw-push` | 0.999 | 0.706 |

Caveat when reading the meta: `mw-*.meta.json` records `eps_max=0.3, noise_max=0.2,
expert_frac=0.3`, but those are unused argparse defaults — the expert branch zeroes them
before use.

> This is why the FB/BC row reads 1.00 ± 0.00 on both Metaworld expert columns. The
> dataset is a saturated single-mode oracle corridor; BC already solves it, and there is
> no headroom left for a critic to earn. (Ph. I.)

## 3. `play-noise`

Same two collectors, `--regime play-noise`. Per **episode** a coin `rng.rand() <
expert_frac` decides "clean"; otherwise draw `eps ~ U(0, eps_max)` and `noise ~ U(0,
noise_max)` once for the episode. Each step then computes

    act = policy(s) + noise · N(0, I)      # Gaussian action noise
    act = U(-1, 1)  with probability eps   # epsilon-random replacement
    act = clip(act, -1, 1)

| task | policy | ε_max / σ_max / expert_frac | shape | ep-success | dwell |
|---|---|---|---|---|---|
| `ms-pick-cube` | TD-MPC2 (`collect_ms_play.py`, `mpc=False`) | 0.25 / 0.15 / 0.3 | 1000×25, obs 42 | 0.772 | 0.272 |
| `ms-push-cube` | TD-MPC2 | 0.25 / 0.15 / 0.3 | 1000×25, obs 35 | 0.955 | 0.691 |
| `mw-pick-place` | scripted oracle | 0.3 / 0.2 / 0.3 | 1000×100, obs 39 | 0.860 | 0.531 |
| `mw-push` | scripted oracle | 0.3 / 0.2 / 0.3 | 1000×100, obs 39 | 0.820 | 0.484 |

Structurally this is still **one target per episode**, held for the whole horizon, with
heavy terminal dwell: the oracle reaches the goal and then sits there for roughly half
the episode. The goal marginal collapses onto a single per-episode point. Only the action
distribution differs from `expert` — not the goal distribution.

## 4. `play-noise-hard` — kill-test, Pred. headroom (Ph. I)

**Generation** (`scripts/collect_playnoise_hard.slurm`): identical collector, identical
episode structure to `play-noise`. Only the mixture is hotter — `expert_frac=0` (no clean
episodes at all), `ε_max=0.5`, `σ_max=0.3`. Horizon, per-episode target, and dwell are
left untouched **on purpose**, so this arm isolates Ph. I from Ph. II/III.

**Contents**: 1000 × 100, obs 39 / act 4.

| task | ep-success | dwell |
|---|---|---|
| `mw-pick-place` | 0.544 | 0.245 |
| `mw-push` | 0.500 | 0.209 |

That is the point: the BC floor falls to ~0.5–0.6 and the benchmark measures guidance
quality again instead of measuring the ceiling.

## 5. `play-resample` — kill-test, Pred. kernel(b) (Ph. III / E7)

**Generation** (`data_collection/collect_mw_play_resample.py`): a different *shape* of
data — OGBench-style play. 200 trajectories × **500 wrapper steps** (= 1000 simulator
steps, cube-play scale). The target is re-drawn from the env's own `goal_space` and
written into `raw._target_pos` (line 91) — exactly the quantity obs dims `[36:39]` and
the scripted oracle read — under two triggers:

- **immediately when `success` fires** (no dwell; the oracle moves on, like cube play), and
- **every `seg_max = 60` steps** regardless, so no segment gets stuck.

`raw.curr_path_length` is zeroed before each wrapper step to defeat Metaworld's
`max_path_length=500` truncation. The exploration mixture is deliberately gentle
(`ε_max = σ_max = 0.1`, `expert_frac=0`): coverage here comes from relocation chaining,
not from action noise.

**Contents**: 200 × 500 = 100k transitions (same budget as the others), obs 39 / act 4.

| task | relocations/traj | dwell | ep-success |
|---|---|---|---|
| `mw-pick-place` | 47.5 | 0.095 | 0.960 |
| `mw-push` | 31.0 | 0.062 | 0.965 |

Each trajectory is a chain of ~30–48 distinct reach-and-move segments, so within-trajectory
relabeling now crosses target contexts through transitions the data actually contains —
the train-side repair of Ph. II. The eval-side fixed-frame conditioning
(`env/unified.py:167`) is **not** repaired, by design. Everything in this arm scores
0.95–0.98 including BC, i.e. it re-saturates.

## 6. `play-resample-hard`

Same collector and same 200×500 structure as `play-resample`, but with
`play-noise-hard`'s mixture: `ε_max=0.5`, `σ_max=0.3`.

| task | relocations/traj | dwell | ep-success |
|---|---|---|---|
| `mw-pick-place` | 3.43 (from 47.5) | 0.007 | 0.655 |
| `mw-push` | 4.91 (from 31.0) | 0.010 | 0.710 |

The hot noise breaks the chaining: relocations per trajectory collapse by an order of
magnitude, because the oracle rarely completes a segment. This is nonetheless the only
arm that is simultaneously **un-saturated and goal-diverse**, which is what makes it the
informative one.

## 7. `cube-single-play-v0` — the three cube arms

Not generated in this repo. The bottom sub-table's arms (`gciql-qb75`,
`biql-d50-nopsiln`, `biGCIQL d=15`; 500k steps × 3 seeds, `scripts/launch_phenomenon_tests.sh`)
train on stock **OGBench `cube-single-play-v0`**, wired through
`env/domains/cube-single.yaml` → `env/ogbench.py` and downloaded to `~/.ogbench/data/`.

Eval differs from every dataset above: it is the mean success over OGBench's fixed
`(init, goal)` `task_infos`, folded into a single row by `eval_aggregate: true`.

## Summary — what varies across the six

The two regimes in the main grid differ **only in action noise**; all four Metaworld
columns share one-target-per-episode structure with heavy terminal dwell. The three
kill-test datasets pull apart the two properties `play-noise` confounds:

| | headroom (BC floor) | goal diversity |
|---|---|---|
| `play-noise` | none (BC ≈ 0.9) | none (1 target/episode, dwell ≈ 0.5) |
| `play-noise-hard` | **reopened** (BC ≈ 0.5) | none |
| `play-resample` | none (BC ≈ 0.96) | **high** (30–48 relocs, dwell ≈ 0.08) |
| `play-resample-hard` | **reopened** (BC ≈ 0.65) | moderate (3–5 relocs, dwell ≈ 0.01) |
